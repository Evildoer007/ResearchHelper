# ThesisBuilder

标识rh_thesis。综合问题回答、机制、竞争解释、反证与验证条件，形成研究论点及投资含义。事实和直接比较无需强制生成投资论点，不规定固定数量。

实现位于modules/thesisbuilder/src，负责问题拆解、论点要求和各推理阶段的输入输出约束，由ResearchAgent按问题依赖安排。Skill仍由当前宿主推理，不为模块另起模型。

需要新数据或计算时交回编排，不在写论点时偷偷取数。主题相关不证明实际暴露，形成论点不代表现在值得买入，不推荐衍生品结构。

主问题answer给出综合结论，各条thesis解释独立的驱动、机制或竞争解释，并保留反证与成立边界。依照共享research_outline关联question_ids及本条calculation_refs，不把主问题的全部数据视为所有论点的支持。只做核对或直接比较时无需策略，论点数量不固定。

首次出稿通过draft_research_context共用入口与意图，并传递当前来源中实际登记的selection_reason和问题关联。规划用途不等于事实，不生成新问题或自动补取资料。来源过期、串任务、失败或损坏时不传递其用途；缺少用途时不推测。普通Chat选择research后，同样采用独立业务判断的论证要求。

投资研究在取数规划时先考虑可检验的驱动及竞争解释，把请求用途与所需依据关联，不把用户点名的几项指标当成全部研究资料。取数完成后按实际覆盖决定补取或调整论点；请求覆盖不等于研究充分性，也不要求把所有缺项补齐才出稿。

App取数规划器先读取本任务已锁定的knowledge_context，结合其中的机制、验证指标与竞争解释选择资料。Skill可用空请求准备相同的本地上下文，不调用数据或模型；未采用的目录、理论及条件均不自动变成数据需求或标的事实。

关联追问是新问题，不继承上一轮发现机会、比较或原件核对等意图限制，采用普通综合研究入口，由当前问题决定报告组织。继续讨论原对象时保留对象入口；更换对象或加入比较时使用混合入口，不根据代码前缀猜资产类型。既有对象指代、历史截止时点及父版本引用保留，旧证据、材料、核验和用量不转成新任务批准。此规则只在创建新追问时执行，不改写已经保存的任务与报告，不新增分类模型调用。
