# ReportComposer

标识rh_report。汇集同任务、同版研究产物，绑定正文数字、引用、范围、缺口及风险，生成冻结内容包。报告保存成功才交付，更新创建新版本。

实现位于modules/reportcomposer/src，负责完整性检查、内容冻结和版本对比；档案事务位于core/src/researchhelper/archive.py。Session.deliver与export使用同一内容和档案契约，App与Skill不各写一套研究结论。

不在交付阶段补取数据或重算数值，不删掉公开论述来凑版面，不把历史案例标记为本轮真实研究。

## 对客策略简报

1. **核心结论**。第一句回答客户问的事。做投资研究时说清截至何时、什么发生了变化、这项变化如何影响投资判断。纯事实或比较只回答对应问题。正文的结论强度随证据调整。
2. **策略逻辑**。每节标题直接写判断，例如「科技回调加深，消费逆势走强」。同一判断的关键比较、解释和投资含义连贯成段，按论述层次分段。用户可以在研究问题里指定条数，实际交付以证据能支撑的独立判断为限。比较历史案例时写明样本期和比较基准，归因须有传导依据。
3. **图表和数字**。一张图解决一个阅读问题。走势需要有序观测，少量离散读数可写在正文；需要对照多个观察窗口时用对比图。图题写对象与比较维度，区间、单位与必要口径就近交代。变化率与百分点分开，正文保留足以表达差异的精度，底稿保留原值。
4. **跟踪标的和风险**。有标的映射依据时才给名称、代码和跟踪理由。把可能改变判断的风险集中在末尾。单位未确认的财务绝对金额保留在底稿；对客正文使用成立的比例或已核实的数值。涉及结论的样本、日期和口径直接写进对应句子。

标准版按A4正文宽度组织，左侧目录在屏幕上保留。首屏能读到标题、资料日期及核心结论，图表贴近对应策略逻辑。内部详细版逐节展开依据、方法、反证和来源。查询过程、接口状态、工作笔记和内部标签留在底稿。

```markdown
# [研究对象与主题]

数据基准日：[日期]

## 核心结论
[截至何时发生了什么变化，对本题的判断是什么。]

## 策略逻辑一：[写出本节判断]
[同口径的区间、对象、基准与数字。解释变化如何影响投资判断。]
[有助于理解的图表与来源。]

## 策略逻辑二：[写出下一条独立判断]
[给出本节比较和解释，交代判断成立的条件。]

## 跟踪标的
[名称与代码。说明该标的衡量哪条逻辑。]

## 风险提示
[哪些变化会削弱核心结论。]
```

按实际问题删减小节，直接核对或比较可省去策略与标的。交付前替换全部占位符。

东吴证券用成交额占比的历史位置说明交易拥挤度。海通证券按时间划分三段行情，对比历史阶段后再给出方向判断。两篇报告的日期、对象及比较基础都与判断同时出现。[东吴证券《接下来市场如何轮动？》](https://pdf.dfcfw.com/pdf/H3_AP202502231643406983_1.pdf)、[海通证券《近期行业轮动的分析和展望》](https://www.htsec.com/jfimg/colimg/upload/20230221/90101676943134654.pdf)

## 内部详细报告

从同版标准报告展开。按每条策略逻辑补齐原始数据及其日期、口径、来源位置，明确哪一步是观察、哪一步是解释。涉及计算时给出公式、输入和结果。将竞争解释与反例写到对应论点，明确新增什么证据会改变判断。

```markdown
# [研究对象与主题]研究详版

数据基准日：[日期]

## 核心结论
[沿用同版标准报告的判断与范围。]

## 策略逻辑一：[沿用对应判断]
1. 观察：[对象、观察期、对照期、原值与单位。]
2. 计算：[公式、输入及明确口径。仅在有计算时填写。]
3. 论证：[事实支持的传导，以及仍成立的竞争解释。]
4. 反证与复核：[何时观察什么指标、什么变化需调整判断。]
5. 来源：[可定位的披露原件、页码、数据系列或字段。]

## 风险与适用范围
[统一汇总高影响风险及仍需核对的关键事实。]
```

## 内容与版本契约

首次草稿的论点聚焦业务判断与经济传导，单位、缺数及流程核验状态不单独构成投资逻辑。可选data_refs与source_refs只关联本任务原值和资料，未知引用记入底稿，不阻断正文。点击逻辑标题或数据值按需查看依据，客户报告不内嵌折叠长文。已引用的单点或不能成图的观测在逻辑旁用紧凑表格显示日期、原值、单位和来源，不补造时间序列。没有图表关联时，已取得原值仍显示在关键数据中。原值表与来源已声明的单位如实保留。

对客正文按核心结论、几条策略逻辑、关键图表、风险提示组织。workpaper_notes只供内部详版，reader_notes只放影响阅读的必要口径。客户正文不展示取数清单、计算账表、核验进度和接口术语；完整原值仍可点击来源读取，内部详版逐条展开。金额单位不明确时不换算绝对金额，相对比较的前提说明一次，不删除影响结论的风险。App与Skill共用first_report.writing_brief。正文避免与具体事实无关的防御性套语。风险写清触发因素和影响。少量可比数据写进句内，需要辨认差距或形态时再配图。底稿保留原件数值、来源和完整计算。

初稿写作与Skill读取相同的精简知识上下文。knowledge_refs只记录实际使用的同任务锁定条目版本，内核附条目哈希；检索结果不会自动变成论据。底稿、报告依据弹层和内部详版展示被引用的理论、适用条件、反例与来源，引用异常与理论分开。缺少知识不阻断正文，旧报告不补记使用记录。

内部详版逐行保留对象代码与指标，缺失原值显示未返回，数据附件仍保留原始空值。少量原值已完整列于相应逻辑时，不再复制同一数据依据表和末尾汇总；大表或未随论点列出的原值仍保留完整集中表。图表引用不等于已列原值，单位依据、实际计算、研究备注和来源继续展开。草稿计算标题写明实际对象和计算期间，展示该结果冻结的适用条件及必要的单位前提，不用通用方法说明替代本次限制。来源显示使用同一名称映射，来源记录的供应商标识和内容哈希不改写。

没有可用正文时，备用内容按必要问题组织：事实核对与直接比较列示原值和口径，不添加盈利、估值或机会论点；机制与投资问题保留待验证研究逻辑。此规则只用于新任务及新版本，原有正文和冻结旧报告保留，不增加取数、模型调用或交付阻断。

数字阈值须有来源、方法或用户设定；自设条件明确标为待验证观察，不写成已验证的拐点、交易规则或预测能力。该要求由App和Skill共用写作规范提供，不新增审查模型或阻断出稿。

投资研究的每条逻辑连接事实、机制、成立条件与反证；资料有限仍可形成条件性假设，不把指标复述或资料缺项单独当成策略。趋势及标题检查完整观测区间，不以两端读数代替中间路径。上述为同次写作指导，不增加出稿阻断或额外模型调用。

App与Skill共用report_writing_example。研究逻辑以argument的claim、evidence、reasoning、condition区分判断、依据、推演与条件，内核按原序编入正文，并保留结构化底稿。analysis旧格式继续可用；混合提交保留两者，不丢正文。可选detail_analysis沿用该论点的原值及计算，在详版展开归因、竞争解释及复核条件。路径图只取同次撰稿明确提供的mechanism，不从指标名称猜测因果，不增加模型调用或出稿门槛。

首次报告中的PE、PB读数可按已引用的同任务原值呈现适当小数位，点击数字查看完整原值和来源。正文数字、指标或主体不唯一时保持原文，不猜对应；未知金额不据此换算，不追加单位。此为呈现规则，原稿、底稿、数据和冻结内容不变。

新任务和显式更新共用first_report.writing_context。投资正文不接收单位未明确的财务绝对金额，只接收其可读状态、原值引用和已登记相对计算；底稿及数据附件保留全部原值。新稿若仍将可对应原值的金额擅自写成元、万元或亿元，内核仅修正明确对应的数值短语，优先采用同版登记比较，保留相邻分析与风险。不能对应的数字不猜匹配，也不阻断报告；原始提案与调整记录分别保存，发生数值修正时使用中性任务标题。旧任务及冻结报告不回填。

新生成的标准报告将图表绑定实际论点引用，跨论点拼出的无关附图不自动进入对客正文；没有引用时仍可按已有数据提供备用图表，不阻断出稿。成对比较只保留本条逻辑实际支持的指标，收入成本差可独立展示，不要求同时引用净利润率。完整原值及历史背景保留在数据与详版，旧冻结报告沿用其呈现版本。

投资逻辑标题表达经济关系和成立方向，核验动作与补数步骤放入workpaper_notes。标题只保留对象与核心议题，不串联数值或核验进度；必要口径前提不删除，但不以缺少某字段单独凑一条策略。

新报告冻结reader_format_version=1。对客数据表的PE、PB读数采用适当小数位，未知单位简写为未确认；点击数据保留完整原值与单位状态，内部详版和数据附件仍使用原始精度。日期仅将有效日历日期分隔，不推定季度或财年。再次整理已展开的论证时不重复追加同一段落，独立补充分析与多行依据保留。

新呈现将已留存官方原件对应到明确的获取渠道，标准正文、依据弹层、内部详版及数据导出共用名称。官方原文沿同任务同版本的目录条目定位，供应商接口仍保留iFinD等原渠道名称。关联或元数据不足时继续显示通用名称，不阻断出稿，不将渠道名称当作发布主体、首发时间或金融适用性的核验。草稿页脚只列进入本报告数据或论点引用的来源，未采用的取数记录保留在底稿。

正文内容包在呈现前单独持久化。页面生成失败、停止或服务重启后，保留同版正文和引用，显式重试交付只重新完成本地呈现与保存，不重新规划、取数或撰稿。内容、知识或方法依赖已变化时不冻结旧检查点；已完成HTML继续复用。成功冻结报告时统一清除旧运行错误，当前渲染节点按实际结果更新，历史失败记录保留。

完整模型原文先绑定同版来源、原值、知识和撰稿上下文，再整理正文。整理失败也走本地重试保存，不能因模型额度已用完而覆盖成简单提纲。上下文改变时保留旧记录，按修改后的问题继续研究；显式提交的新正文优先，既有原文不冒充新模型返回。

App模型及Skill宿主的完整原文在整理前分别保存，使用共同的本地恢复流程。宿主原文绑定同版底稿；默认draft与resume只在未提交新稿、新请求且原文依赖未变时继续保存，不替换成提纲、不重复登记原文。旧版原文记录保留原样，记录能力不足不阻断首次出稿，也不自动提升为已核验。

对客呈现规则2按本任务已提交或实际尝试的iFinD固定财务请求与可用原值确定比较期间，区分证券、字段和报表口径。单期不写成两期齐备；缺期在核心结论旁简述客观范围，其他原值和论述继续交付，不增加模型调用或出稿阻断。只规范报告对自身资料范围的明确陈述，否定、假设和原件引用保持原文，原始模型回复及修改依据留在底稿。资料补齐后重新计算范围，不沿用失败记录。旧规则1与已冻结内容不迁移。
