2. 五分钟开始

第一次使用时，先完成设置，再用一个普通行业问题走通研究流程。暂时不要从复杂事件或多标的报价开始。

打开设置并完成连接测试至少配置 DeepSeek 和 iFinD；事件搜索再配置 Tavily；需要报价时再配置 OptionHelper。
输入一个明确问题例如：“分析未来一个月机器人行业的投资机会。”
确认研究取数目标在标准行业、人工主题篮子和主题 ETF 中选择一条路径。
审核候选论点勾选真正回答客户问题、且有数据或材料支持的 2—3 条论点。
检查报告并导出预览一页通，必要时编辑文字或删除图表，再导出 PDF。
需要产品时再进入报价选择挂钩标的和结构，完成 OptionHelper 正式报价；研究报告本身不依赖报价成功。
建议的第一次测试问题：“分析未来一个月机器人行业的投资机会。”它能覆盖需求解析、目标确认、行业取数、论点审核、报告预览和历史任务。

1. 产品能做什么

Research Helper 是面向投研分析师的桌面应用。它把客户原始问题、市场数据、上传材料和公开证据整理为一份可复核的研究报告，并可在研究完成后接入 OptionHelper 生成场外衍生品结构候选和正式参考报价。

客户问题主题、期限、风险偏好、点名证券
→
需求解析研究什么、是否事件型
→
目标确认行业 / 篮子 / ETF
→
取数与论点行情、基本面、材料和证据
→
报告交付预览、编辑、HTML / PDF
→
可选报价画像、结构、正式报价

适合

  • 行业或主题未来一段时间的投资机会；
  • 单只 ETF/指数的表现、风险和配置价值；
  • 外部事件对 A 股行业、公司篮子或 ETF 的影响；
  • 已有研究材料的归纳、数据验证和一页通交付；
  • 研究完成后的挂钩标的筛选与结构报价。

不等于

  • 自动替代分析师作出最终投资判断；
  • 在没有数据和原文时补造事实；
  • 把研究取数 ETF 自动当成最终产品标的；
  • 绕过证券真实性、主题暴露、流动性或报价校验；
  • 无需审核即可直接外发的全自动研报。
两个对象必须分清：“研究取数目标”决定报告分析哪些数据；“挂钩标的”决定后续对哪个证券推荐产品和报价。它们可以相同，也可以不同，并且分别确认。

3. 首次设置

首次启动向导只需要填写你有权限使用的服务。没有配置的可选能力会保持不可用，不影响其它已配置功能。

能力是否必需作用首次使用建议
DeepSeek API研究必需需求解析、研究规划、写作和证据分类填写 API Key，刷新模型目录，分别选择快速模型和质量模型并测试连接。
iFinD完整取数必需证券身份、行业成分、行情、基本面、ETF事实等Windows 配置官方 SDK 与账号；macOS 使用获授权的 HTTP Refresh Token。
Tavily事件研究建议公开网页搜索与正文清洗填写 Key，优先选基础搜索；资料难找时再使用高级搜索。可启用 Bing RSS 兜底。
OptionHelper正式报价才需要结构候选、定价参数和正式参考报价只填写已经构建并验收通过的 Skill 路径和独立 Python 环境。

推荐设置顺序

  1. 在“LLM 设置”刷新实时模型目录，测试快速档与质量档；
  2. 在“iFinD 凭证”填写授权信息并运行环境检查；
  3. 在“搜索设置”填写 Tavily Key、语言/地区，点击测试连接；
  4. 确实需要产品报价时再配置 OptionHelper；
  5. 保存设置后重启应用，再运行环境检查。
不要截图或外发设置页面中的秘密。API Key、iFinD 账号密码、Refresh Token 和内部路径都属于本机配置。说明书截图时请先遮挡。

5. 怎样提出问题

好的问题至少说明“研究什么”。期限、关注点和点名证券会提高结果针对性，但不是所有问题都必须同时包含。

推荐结构

研究对象 + 研究期限 + 想回答的问题 +（可选）点名证券/公司 +（可选）产品约束
行业型：分析未来一个月机器人行业的投资机会，重点关注订单、盈利和估值。
主题型：分析未来半年锂电池与固态电池产业链，关注碳酸锂价格、技术进度和应用普及。
单只 ETF：分析机器人ETF 562500.SH 近1个月和3个月表现、波动率、回撤、成交情况及未来一个月展望。
事件型：英伟达新一代 AI 芯片开始放量交付，分析对 A 股光模块行业未来三个月的影响。
多公司篮子：分析消费电子创新周期，并重点研究立讯精密、歌尔股份等客户点名公司。

系统当前需要什么

  • 能够识别一个研究主题、标准行业、公司篮子或主题 ETF；
  • 证券代码使用数据源格式，例如 562500.SH、159995.SZ；
  • 如果只写代码，最好同时写 ETF 名称或主题，避免名称查询失败时主题为空；
  • 需要研究明确事件影响时，勾选“事件驱动型”；
  • 客户产品约束可填写在专用栏，不必混进研究主题。
避免：“帮我看看”“最近怎么样”“推荐一个产品”这类没有研究对象的句子。系统无法据此确定应该取哪个行业、哪些公司或哪只 ETF 的数据。

6. 选择研究取数目标

需求解析后，所有研究都必须经过目标确认。三条路径互斥，本次报告只能选择其中一条作为主要研究口径。

标准行业

数据来自：iFinD 可以验证并取得成分股的行业节点。

适合：机器人、半导体、食品饮料等行业整体研究。

注意：主题名称不一定等于标准行业名称。

人工主题篮子

数据来自：分析师逐只勾选、完成证券身份和业务关联审核的公司。

适合：光模块、固态电池等跨行业细分主题。

注意：系统候选默认不代表核心公司。

主题 ETF

数据来自：ETF 官方跟踪指数的真实成分。

适合：客户明确研究某只 ETF，或 ETF 是最清晰的主题篮子。

注意：需要真实性、跟踪指数、主题暴露和流动性校验。

怎么选

客户问题建议路径原因
“机器人行业未来一个月怎么样？”标准行业或主题 ETF若数据源有合适行业节点可按行业成分；若客户关心 ETF 表现则按 ETF 真实成分。
“光模块产业链机会”人工主题篮子光模块属于细分主题，标准行业可能过宽。
“分析 562500.SH 的表现”主题 ETF研究对象已经是具体 ETF；行情指标使用 ETF 自身，成分研究使用跟踪指数成分。
“锂电池和固态电池，并研究客户点名的五家公司”人工主题篮子只采用分析师确认的客户点名公司，ETF 留到后续报价确认。
ETF 暴露等级：直接暴露可以继续；部分暴露需要分析师核对跟踪指数和主要成分、填写映射理由；不相关会停止该 ETF 路径。流动性最低要求与优选水平分别显示。

7. 普通研究完整操作

粘贴客户原始问题尽量保留原文，不要先把客户问题改写成自己的结论。
填写客户约束期限、最大损失、本金波动和收益偏好主要供后续产品审核使用。
按需加入材料可上传 PDF 或粘贴文字，并填写来源和材料日期。
启动研究并检查解析结果核对研究主题、体裁、关注点和客户点名证券。发现方向错误时应返回修改。
确认取数路径选择标准行业、人工主题篮子或主题 ETF，并核对映射理由。
等待取数与候选论点运行进度会显示当前阶段；外部接口较慢不等于程序卡死。
勾选正文论点优先选择直接回答客户问题、有明确数据日期和来源的 2—3 条。
检查一页通检查标题、结论、图表、来源、数据日期和一页校验，再决定是否进入产品报价。
看到缺口时：不要为了让流程通过而随便补数字。可返回调整取数目标、补充有来源的材料，或保留缺口并停止不可靠结论。

8. 事件驱动研究

IPO、业绩/指引、政策、产品发布、产能变化等明确外部事件，建议勾选“按明确外部事件处理”。科技回调、风格轮动等市场状态通常使用普通研究，不必强行填写事件证据。

事件事实到底发生了什么
→
产业机制供需、价格、技术或竞争格局如何变化
→
A股暴露所选行业、公司或 ETF 为什么相关
→
组合传导链形成可写入报告的研究逻辑

操作步骤

  1. 在主界面勾选事件驱动型；
  2. 点击“管理事件证据”，可先自动查找候选；
  3. 逐条核对原文、日期、来源和对象，勾选可采用内容；
  4. 先确认研究取数目标，系统再针对本次行业、篮子或 ETF 补搜 A 股暴露；
  5. 检查组合传导链是否真正解释“为什么影响本次研究对象”；
  6. 候选论点中至少选择一条由确认事件证据支持的事件主轴。
“搜索到”不等于“证据完整”。纯股价播报、走势图、搜索摘要和没有正文的网页不能代替事件事实或产业传导原文。系统不会自动采用任何候选。

9. 补充材料

上传 PDF

适合研报、公告、访谈纪要和正式材料。系统会提取原文，保留文件名、页码和材料日期。

粘贴文字

适合网页摘录、客户补充说明和短材料。必须填写来源，建议同时记录发布日期或数据日期。

材料使用原则

  • 材料进入候选证据，不会自动覆盖市场数据；
  • 过期、未来日期或日期不明的材料需要人工确认；
  • 报告中的数字必须有明确口径和日期；
  • 客户提供事实、公开原文、行情数据和系统分析要能够区分；
  • 不要上传无权使用或不应留存在本机的材料。

10. 报告、编辑与导出

自动报告完成后先看“交付与报价”页。正式交付前应检查：标题是否回答客户问题、核心结论是否简洁、每张图是否有清楚标题和来源、数据日期是否明确、PDF 是否实测为一页。

可以编辑什么

文字

报告标题、核心结论、逻辑标题、正文和图表标题。

结构

论点顺序、论点显隐、图表显隐和删除单张图表。

交付

保存修订版 HTML、重新导出 PDF、打开产物目录。

自动稿不会被直接覆盖。人工修改保存为修订版；删除图表后，剩余图表和文字会根据图形尺寸重新排版。每次导出 PDF 都会重新检查真实页数。

一页校验失败时：先精简重复文字和低价值图表，再检查字号与布局。不要通过极端缩小字体让内容勉强塞进一页。

11. OptionHelper 产品推荐与正式报价

这是研究完成后的独立支线。只想生成研究报告时可以完全不进入该流程。

选择待报价标的客户点名或研究工具
→
产品画像收益、波动率、回撤、流动性
→
结构候选OptionHelper 独立推荐
→
人工确认逐标的选择结构
→
正式报价定价数据与条款
→
写入一页通分析师勾选结果

注意事项

  • 系统自动发现的同主题 ETF 不会全部默认弹出；需要时点击“比较其他同主题工具”；
  • 每只标的独立推荐，某只“无候选”不影响其它标的；
  • 产品画像用于推荐前审核，不替代 OptionHelper 的正式定价数据；
  • 结构候选必须由分析师确认，正式报价失败不删除已完成的研究报告；
  • 报价完成后，由分析师选择哪些产品写入一页通，不按胜率自动筛选。
状态理解：recommending 表示结构推荐；quoting 表示正式定价；finalizing 表示报价已经返回，正在同步底稿、HTML 和 PDF。

12. 历史任务

  • 在左侧搜索框输入主题、代码或客户问题关键词；
  • 同一完整问题的重复运行会合并展示；
  • 可把长问题重命名为简短标题，原始客户问题不会被修改；
  • 打开历史任务可查看当次报告、运行摘要、底稿和交付文件；
  • 历史报告默认只读，点击“编辑此报告”会创建独立修订版；
  • 若最新一次运行失败但旧报告存在，界面会明确提示当前展示的是此前版本。

13. 常见问题

显示“尚未形成取数目标”
系统没有形成可用的标准行业、公司篮子或主题 ETF。检查问题是否写明研究对象；若已输入 ETF 代码，同时补充 ETF 名称或主题。确认 iFinD 可用，并查看候选淘汰原因。
DeepSeek 网页能用，但应用 API 失败
网页会话和 API 是两套服务。检查 API Key、接口地址、网络权限和账号可用模型；在“LLM 设置”刷新模型目录并测试。
事件证据只找到产业机制
事件主体、时间或动作可能不够明确，或事件事实网页无法读取。补充公司全称、公告/业绩/发布等动作和日期；优先采用公司、交易所或监管原文。
主题公司看起来不相关
先看候选来源和关联等级。概念股命中只是线索；没有具体业务原文的公司不应预勾选。可补充依据、删除候选，或改用主题 ETF 真实成分。
研究完成但没有正式报价
检查是否勾选待报价标的、是否确认结构，以及 OptionHelper Skill、独立 Python、凭证和正式条款是否完整。报价失败不会影响研究报告。
一直显示正在重建最终 PDF
先查看报价任务是否已进入 finalizing。若长时间不结束，保存 quote id 和运行记录，重启应用后从历史任务检查研究报告是否已生成。
安装版启动时报找不到 main.py、core 或 tool_entry
确认使用最新版完整安装包。便携版必须完整解压，不能只复制 EXE。tool_entry 属于 OptionHelper Skill，需使用构建并验收后的 Skill，而不是源码仓库。
报告超过一页
在编辑器删除低价值图表、压缩重复论述并重新导出。以重新读取的真实 PDF 页数为准。

14. 安全与交付前检查

每次研究前

  • 客户问题和研究期限完整
  • DeepSeek 与 iFinD 状态正常
  • 事件型任务已确认搜索服务
  • 材料具有使用权限与来源日期
  • 需要报价时 OptionHelper 已就绪

外发报告前

  • 研究对象与标题一致
  • 数字有日期、单位和来源
  • 结论没有内部审核术语
  • 报告未显示内部证据编号或底稿提示
  • PDF 实测为一页
